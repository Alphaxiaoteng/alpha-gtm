# Browser Agent Control Overlay 设计

日期：2026-07-30
状态：已批准并按 2026-07-30 EgoLite 视觉反馈修订

## 目标

当 Alpha-Nexus 的发布 Worker 通过本机 CDP 操作 fingerprint-chromium 时，在网页内容区明确展示 Agent 即将执行和正在执行的动作，让用户看见目标控件、点击位置和当前控制权。

首版只接入 `internal/publishworker/worker.cjs`。它不改变发布状态机、选择器判断、最终提交审批或人工接管边界。

## 范围

首版包含：

- EgoLite 风格黑色 Agent 光标平滑移动到目标控件；
- 光标旁显示基于控件可访问名称的具体动作说明；
- 点击时显示一次波纹；
- 页面底部显示任务名、控制状态、“接管”和“终止任务”；
- 页面导航或刷新后恢复动画层；
- 尊重 `prefers-reduced-motion`。

首版不包含：

- 覆盖 Chromium 标签栏、地址栏或系统窗口；
- 浏览器扩展；
- 发布 Worker 以外的登录观察、只读检测和普通浏览器启动动作；
- 绕过验证码、2FA、checkpoint 或最终提交审批；
- 接管后的同一 Worker 原地恢复；“交还给 Agent”必须等待可恢复控制协议，首版不放置假按钮；
- 新的后台服务、依赖或持久化表。

## 方案

采用方案 A：由现有发布 Worker 通过 Playwright/CDP 向当前网页注入一个无依赖的视觉层，并在真实动作前后调用视觉提示。

不采用以下方案：

- 在 `BrowserFacade` 中全局注入：Facade 管理浏览器生命周期，但不知道 Worker 当前要操作的 DOM 控件。
- Chromium 扩展：需要额外权限、安装和打包链路，超过首版需求。

## 组件

### 页面视觉层

视觉层使用固定定位的 Shadow DOM 根节点，避免平台页面 CSS 污染它，也避免它修改平台 DOM 布局。

它包含：

- 不接收指针事件的 Agent 光标；
- 不接收指针事件的动作气泡；
- 不接收指针事件的点击波纹；
- 唯一接收指针事件的底部控制条。

所有节点使用固定、命名空间化的标识。重复注入必须复用现有根节点，不得产生多个控制条。

### Worker 视觉控制器

Worker 内提供 `createAgentControl(page, { taskLabel })`，返回 `race(operation)` 和
`dispose()`。页面捕获 Playwright 产生的 pointer、focus 和 click 事件，使用
`aria-label`、关联 label、placeholder 或按钮文字生成短动作名称；不读取输入值，
不把动作名称写入日志。不得把 Cookie、正文、完整 URL 或 profile 路径写入页面或日志。

### 接管信号

用户点击“接管”后，页面视觉层设置页面内存请求。Worker 以 50ms 轮询把原有操作与
接管请求竞速；接管获胜时返回现有安全边界兼容的 `manual_takeover` 结果。点击
“终止任务”返回 `WORKER_CANCELLED`，不能标记为发布成功。

首版不承诺撤销已经发送到浏览器的单次原子点击；Worker 进程返回结果后立即断开自己的
CDP WebSocket，不关闭用户浏览器。

最终提交仍受冻结单目标计划和 `submit-bound` 单次审批约束。视觉层不能创建、替代或重复最终提交。

## 数据流

```text
发布计划 / Tool Agent
  → publishworker 选出已验证 Locator
  → 视觉控制器显示任务名并观察真实指针/聚焦动作
  → 原有操作与接管/终止请求竞速
  → 执行原有 Playwright 动作
  → 播放点击反馈
  → 原有回读与发布证据判断
```

页面导航后由 Playwright 的 `domcontentloaded` 监听器重新安装视觉层；任务结束时移除
监听器和页面节点，不留下跨任务脚本。

## 交互与样式

- 光标使用高对比度黑色箭头、白色描边和阴影；
- 动作气泡使用深灰圆角胶囊，最多一行，显示“填写视频描述”“点击上传”等具体动作；
- 底部控制条参考 EgoLite 的黑色宽胶囊，固定居中并距离视口底部 20px，宽度不超过 860px；
- 控制条显示暂停符号、运行指示器、平台任务名、控制状态、“接管”和橙红色“终止任务”；
- 动画时间保持短促；系统要求减少动态效果时改为无位移的即时状态切换；
- 控制条必须支持键盘聚焦，接管和终止按钮具备明确的可访问名称。

## 错误处理

- 注入、定位或动画失败：记录脱敏诊断，清理残留视觉状态，原有 Worker 行为继续；
- 接管请求：停止新的可变更动作并返回 `manual_takeover`，不能标记为发布成功；
- 终止请求：返回 `WORKER_CANCELLED`，不能标记为发布成功；
- 页面关闭或目标失效：沿用原有 Locator/Worker 错误处理；
- 任务完成、失败或取消：尽力清理视觉层；清理失败不得覆盖原任务结果；
- 视觉层不得吞掉平台页面的鼠标或键盘事件，控制条区域除外。

## 测试

按 TDD 先写失败测试，再实现：

1. Node 单元测试验证重复安装、具体动作名称、点击反馈和清理；
2. Node 单元测试验证接管与终止请求分别返回 `manual_takeover` 和 `WORKER_CANCELLED`；
3. Node 单元测试验证动画注入失败不改变原动作结果；
4. Node 单元测试验证严格 CSP、`prefers-reduced-motion` 和键盘可访问性；
5. 发布 Worker 现有测试回归，确认审批、回读和成功证据契约未变化。

不以动画出现作为发布成功证据。

## 验收标准

- 设置中账号当前使用的 Chromium 浏览器网页内容区能看到黑色 Agent 光标、具体动作说明和点击波纹；
- 刷新或导航后下一次动作仍能恢复视觉层；
- 点击“接管”后不再开始新的可变更动作，任务进入 `manual_takeover`；
- 点击“终止任务”后 Worker 返回 `WORKER_CANCELLED`；
- 人工点击网页其他区域不被视觉层拦截；
- 减少动态效果模式下没有平滑移动或呼吸动画；
- 原有发布审批、状态和证据测试保持通过；
- 不新增依赖、数据库表、服务或浏览器扩展。

## 后续升级边界

首版稳定后，若其他 Agent 浏览器动作也拥有统一的“目标 Locator + 动作名称 + 接管检查”接口，可复用同一视觉控制器。首版不为尚不存在的统一动作总线提前增加抽象。
