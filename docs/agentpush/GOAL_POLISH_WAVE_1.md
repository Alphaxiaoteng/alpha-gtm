## 1. 四项外部能力的最终裁决

### 1.1 命名澄清（必须纠正的前提）

- **`rust-anything` 不是性能库。** 它是「逐单元把 TS/Python/C/Go/Java 迁到 Rust，并用录制的行为做回归」的迁移工具链（`analyze → bridge → record → diff → bench → gate`）。装在本机也只会加速*迁移过程*，不会加速*运行中的程序*。
- **它的 Go 路径走 cgo 桥接**：对 Go 意味着 cgo 调用开销 + 交叉编译复杂度（darwin arm64/amd64 + linux 四个目标）。本项目是单开发者本地工具，端点已是毫秒级，收益撑不起维护成本。
- **裁决：Wave 1 不引入。** 保留现有 `rust/screen-encode` 那种「可选子进程、缺失即回退」的模式作为唯一 Rust 接入方式。若将来某个热点函数确实需要，再用 `rust-anything profile` 定位 + 手写 sidecar，而不是全仓 cgo。
- 该工具**已安装且可用**（v2.0.2，`rust-anything doctor` 可查），留档备用，不写进构建。

### 1.2 新浪采集（多平台爬虫类参考）

- 该生态里最知名的项目采用 **Playwright + 持久化 cookie + CDP 复用已登录 Chrome**，且 README 明确**禁止商业用途**。
- 与本项目三条硬约束冲突：不存 Cookie、不绕验证码、不做云后台。
- **裁决：不 vendor 任何代码。** 只吸收两样东西：①各平台**页面结构的稳定性知识**（哪些字段在 SSR、哪些在 XHR），②评论/分页的**遍历策略**。数据获取优先走已有的 TikHub API 通道——它是一条合规、可计费、无需登录态的路径。
- 代码里不得出现该等项目的名称、作者名或文件结构痕迹。

### 1.3 yt-dlp（视频/音频/逐字稿）

- 已装 `yt-dlp 2026.08.19` + `ffmpeg`。**未装 `mlx-whisper`**。
- **裁决：采用，作为可选子进程**，与 `screen-encode` 同一模式：二进制缺失时功能降级、绝不阻塞主流程。
- 硬规则：**不传 `--cookies-from-browser`**，不读浏览器 profile。只处理公开内容；需要登录的平台在 UI 里明确标注「需人工在浏览器内操作」并停止。
- 逐字稿三级降级：平台字幕 → `mlx-whisper` 本地转写 → 提示用户。
- 落地为 `internal/transcript`，CLI 与 Tool Registry 共用同一能力面。

### 1.4 去 AI 味（文案自然化）

- 拆两类：**可验证的自然化规则**（删套话、变句长、具体化、去对冲、去三段式排比）vs **检测器规避**（不应承诺）。
- **裁决：只做前者。** Go 规则引擎 + 用户可编辑规则表（JSON），不依赖外部服务，不做任何「绕过 AI 检测」的表述。

## 2. 已确认缺陷（有证据，非猜测）

### P0-1 日志文件无限增殖 —— 6587 个文件

`internal/tools/tools.go:236`

```go
path := filepath.Join(rt.DataDir, "logs", fmt.Sprintf("events-%d.jsonl", os.Getpid()))
```

每个进程一个文件，`observability.FileEmitter` 只做**单文件内**的大小轮转（10 MB × 5 份，`file.go:18-19`），**从不回收已退出的进程文件**。6587 个 PID 就是 6587 份永不清理的日志。

- 影响：`logs` 目录列表、备份、Spotlight 索引、用户「日志」页都变慢；磁盘只增不减。
- 修法：按**天**归档（`events-YYYYMMDD.jsonl`）+ 保留策略 + 启动时清扫孤儿文件。

### P0-2 数据目录冗余 ~560 MB

- 4 份陈旧 DB 快照（118+112+119+112 MB），且都带 `-shm`/`-wal`
- 2 份旧二进制（各 34 MB）
- `trend-radar/creators/douyin/<id>/media` 227 MB + `snapshots` 161 MB，无保留策略

- 修法：设置页「存储」区给出可读占用 + 一键清理；媒体按「最近 N 天 / 保留上限」自动淘汰；DB 备份只留最近 1 份。

### P0-3 设置项散落

`SettingsView.tsx` 已 3262 行、单页堆叠；另有至少 7 处设置在各自模块里（localStorage / 独立 section），存在重复与默认值冲突。

### P0-4 日志入口在前台

`SystemLogsView` / `RuntimeMonitorView` / `OperationActivityPanel` 把原始事件流放在一级导航里。按需求应改为**全局后台抽屉**，由设置页控制保留与级别。

## 4. 执行顺序（每步独立可验证）

1. **日志生命周期** — 按天归档 + 保留 + 启动清扫；补测试
2. **数据目录卫生** — 存储占用 API + 清理入口 + 备份保留
3. **设置归口** — 8 组 IA，先做迁移层（旧 key 自动读入），再改 UI
4. **后台抽屉** — 日志从一级导航移到全局抽屉
5. **yt-dlp 通道** — `internal/transcript`，可选子进程，公开内容
6. **去 AI 味规则引擎** — 规则表 + 预览
7. **内容阶段事件** — 新增表 + 单调性校验 + 补事件
8. **前端瘦身** — 最大 chunk 拆分、首屏资源数下降
9. **深度测试** — Go 全量 + UI 测试 + e2e 冒烟
