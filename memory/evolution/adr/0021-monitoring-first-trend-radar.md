# 0021. 趋势雷达以博主与赛道监控为主

| 字段 | 值 |
|------|-----|
| Status | accepted |
| Date | 2026-07-25 |
| Area | trend-radar, tikhub, ui, local-storage |

## Context

公开日榜容易在平台内直接查看，不能形成 Alpha-Nexus 的长期价值。实际运营更需要持续盯同赛道内容和对标博主，并把常用搜索词、每次抓取和历史变化保存在本机。评论分析不属于当前趋势雷达主链。

## Decision

- 一级结构收敛为监控总览、博主监控、赛道监控、常用搜索词。
- 默认提供 AI赛道和情感赛道；用户可编辑赛道、搜索词、启停状态和平台。
- 精选 TikHub 目录移除 `daily_rank` 与 `comments`，只保留搜索、内容详情、博主资料和博主作品。
- 趋势雷达读取统一 `tikhub/calls` 原始快照，不再读取 `tikhub/ranks`。
- 抖音和小红书博主刷新分别调用资料与作品接口；加入或移除名单本身不联网。
- 监控仍是显式刷新，不建立后台轮询。每次真实调用显示平台、搜索词数量或接口数量并请求确认。
- 搜索结果按赛道聚合，保留搜索词、平台、首次/最近发现、出现次数、来源和可用互动指标。
- 爆款与选题是监控信号的下游动作；选题只保存本地草稿。

## Consequences

### 正

- 页面直接服务“盯人、盯赛道”，而不是复制平台热榜。
- AI 与情感赛道开箱可用，搜索词和平台可轻量调整。
- 配置、调用记录、完整响应和分析结果都可追溯、可恢复。
- 删除评论与榜单接口后，TikHub 目录从 30 个收敛为 21 个。

### 负 / 代价

- 当前不会自动按计划刷新；用户需要主动触发。
- 首次只有单次快照时只能标记首次发现，增长判断需要后续同词同平台快照。
- 跨平台结果结构仍需持续维护保守的本地归一化规则。
