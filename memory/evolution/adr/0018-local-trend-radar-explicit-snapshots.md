# 0018. 趋势雷达采用显式采集与本地可追溯快照

| 字段 | 值 |
|------|-----|
| Status | accepted |
| Date | 2026-07-25 |
| Area | tikhub, browser, ui, data |

## Context

国内内容运营需要同时看抖音、小红书和文章平台的趋势、博主、爆款、选题与评论信号。现有 TikHub 客户端、XHS BrowserFacade 采集和本地内容库可以复用，但不能引入第二套浏览器生命周期、云端真源或后台周期采集。

第三方接口与网页采集都可能出现限流、登录墙、字段变化和部分失败。失败不能被解释为 0 条内容，选题和爆款判断也必须保留来源、榜单与指标证据。

## Decision

- 公开结构化数据优先走 TikHub；需要本机登录态或尚未验证公开接口的平台走 BrowserFacade / CDP 或显式链接导入。
- Playwright 继续只用于 E2E 或未来由 Go 控制面调度的可选 worker，不替换 BrowserFacade。
- 页面加载只读取本地快照。TikHub 网络同步必须由用户点击并确认；不轮询、不建立本地调度器。
- 榜单、搜索和博主原始响应写入本地 JSON；SQLite 保存账号、内容草稿和后续可查询索引。视频文件仅在用户逐条明确选择时归档。
- 每条趋势/选题保留平台、榜单、排名、抓取时间、原链接和可用指标；不提供无证据的“AI 爆款预测分”。
- 评论洞察采用“规则预筛 → 可选模型复核 → 人工复查”，保留算法版本与失败状态；未接入评论快照时显示“未采集”，不显示 0。
- 第一阶段绑定抖音榜单和小红书博主快照。供应商存在但应用尚未接线的平台显示“可接入”，未验证的平台显示“浏览器 / 链接导入”。

## Consequences

### 正

- 单机可查看、可备份、可追溯，第三方接口短时不可用时仍能读取最近快照。
- 网络成本、登录态与失败状态对用户可见，不会静默采集或伪造成功。
- 复用现有 Go、SQLite、Tool Registry 与 BrowserFacade，不新增常驻服务或前端栈。

### 负 / 代价

- 页面不是实时流；新鲜度取决于用户主动同步。
- 文章平台和抖音博主监控需要逐项接线并验证，当前不能宣称全平台自动监控。
- 跨日增速、评论聚合和统一趋势评分需要后续 SQLite 索引；V1 只展示来源榜单与明确指标。

## Alternatives

| 方案 | 为何未选 |
|------|----------|
| Playwright 常驻抓取所有平台 | 分叉浏览器主线、增加登录态与风控成本，并违反无周期采集边界 |
| 只使用 TikHub | 无法覆盖自有账号后台与未验证平台，也会把本机控制权交给单一供应商 |
| 将完整视频默认下载到本地 | 磁盘与版权成本过高；元数据和证据快照足够支撑 V1 分析 |
