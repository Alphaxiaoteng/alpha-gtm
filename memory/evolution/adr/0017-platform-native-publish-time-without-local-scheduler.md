# 0017. 显式发布准备可填写平台原生时间但不建立本地调度器

| 字段 | 值 |
|------|-----|
| Status | `accepted` |
| Date | 2026-07-24 |
| Area | publish |

## Context

内容库已有 `planned_at` 编辑排期，用户希望一键发布时复用该时间。项目仍禁止后台定时器、到点唤醒和无人值守发布；第三方平台的时间控件及允许范围也可能变化。

## Decision

用户显式点击“一键发布”的准备动作时，把冻结内容的 `planned_at` 复制到每个目标的不可变 `publish_at`，并尝试填写第三方平台原生“定时发布”控件。

- 冻结计划与真正操作平台前均校验时间，当前统一下限为至少提前 15 分钟。
- Alpha-Nexus 不创建本地计时器、不在到点时启动浏览器或再次提交。
- 平台控件必须精确匹配并回读成功；缺少证据或回读不一致时进入 `manual_takeover`。
- 最终发布按钮仍需独立、当次明确授权。

## Consequences

### 正

- 内容库排期可直接复用，视频组和文章组账号获得同一冻结时间。
- 应用退出或重启不影响平台已接受的原生排期，也不引入本地后台任务。
- DOM 漂移不会被误报为填写成功。

### 负 / 代价

- 平台原生时间范围可能比统一下限更严格；页面不接受时需要人工调整。
- 未经真实账号验收的平台只能保守进入人工接管。

## Alternatives

| 方案 | 为何未选 |
|------|----------|
| 本地定时器到点自动发布 | 扩大后台副作用、恢复与账号风控范围，违反只执行当次明确动作 |
| 只把排期当日历备注 | 无法满足一键发布复用时间的明确需求 |
| 猜测平台 DOM 并直接写值 | 可能写错控件或伪报成功 |
