# VCat 会员能力参考（仅候选）

> 来源快照：同级本地仓库 `../vcat-matrix`，复核日期 2026-07-18。该仓库是参考资料，不是 Alpha-Nexus 的运行时依赖。

## 证据边界

- `docs/16-AUTH-MEMBERSHIP-ENTITLEMENTS.md` 明确要求价格、套餐、账号上限和付款流程重新取证，不能硬编码。
- `docs/modules/identity/module.json` 将身份会员模块标为 `blocked`、`mock_only`、`draft`。
- 规格要求的 `entitlements-current.json` 当前不存在，精确权益矩阵仍缺证据。
- 当前源码没有该规格设想的 identity/entitlement 实现，规划中的表和 command 不能当作可迁移代码。
- 会员文档列出的评论/私信、监控、批量商品、平台草稿、追评、独立代理、离线提醒和云同步，多数仍是候选、Mock 或 blocked。

## Alpha 可以借鉴

| 候选语义 | Alpha 的最小用法 |
|----------|------------------|
| 能力状态统一为 enabled / quota_reached / expired / not_in_plan / suspended / unknown | 仅在未来确有商业化需求时采用中央判定；快照需带 source / checkedAt / expiresAt / limit / used / reason，过期缓存进入 unknown，危险能力默认拒绝 |
| 失权不删除数据 | 保留账号、草稿、素材和历史；未开始项阻断，运行中或结果未知项进入对账，不因失权重复执行 |
| 执行前重检 | 当前继续复用现有账号归属、确认和幂等门禁；未来若启用权益，只在同一个最终副作用门禁加入状态、有效期和配额重检，不另建执行层 |
| 表单不因无权丢失 | 阻止执行时保留当前输入并给出明确原因 |
| Agent 权限不高于用户 | Agent 继续不能提权、确认或静默发布 |
| 会员候选中的并发、代理和离线能力 | 不复制 VCat 的并发或调度实现；Alpha 只保留现有 Fleet 有界并发、现有代理池和只读运行概览 |

产品配额与防资源耗尽的安全上限必须分开：账号数、素材数和并发限制不能仅因套餐升级而绕过安全边界。

## 暂不引入

- 产品扫码登录、手机号绑定、会员中心、支付/续费/退款/发票；
- 子账号、席位、复杂 RBAC、SSO、组织审批；
- 云同步、后台权益轮询、离线调度、自动回复和监控调度；
- 第二套代理池、代理评分/自动轮换、无限并发；
- 新的会员一级导航或为候选规格提前新增 API、表、服务和事件总线。

Ponytail：只有出现明确商业化 Goal、当前证据和验收环境时，才把上面的候选语义提升为实现计划。
